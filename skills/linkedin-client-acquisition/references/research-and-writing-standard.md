# LinkedIn Research and Message-Writing Standard

This reference governs discovery, evidence handling, contact-path selection, and the quality bar for every LinkedIn message. It is intentionally specific to the user's web development, ecommerce, custom software, integrations, and automation services.

## Discovery query pack

Search LinkedIn public posts first because a specific request or stated problem is stronger than a profile title.

### Direct service requests
- "looking for a Shopify developer"
- "recommend a Shopify developer"
- "need a web developer"
- "looking for a website redesign"
- "need a web development agency"
- "looking for a technical partner"
- "need a custom dashboard"
- "looking for CRM integration"
- "need a web application"
- "looking for AI automation"
- "need workflow automation"
- "looking for a custom CRM"
- "need an internal dashboard"
- "need a booking system"
- "looking for booking integration"
- "need API integration"
- "looking for an integration developer"
- "looking for a contract developer"
- "seeking freelance full stack developer"
- "looking for freelance developers"

### Agency partnerships
- "white label development"
- "development overflow"
- "need a development partner"
- "looking for a reliable developer"
- "agency needs frontend developer"
- "agency needs full stack developer"

### Decision-maker discovery
- Founder / Owner of an ecommerce brand or Shopify store.
- Founder / Co-Founder of a SaaS or software startup.
- Owner / Managing Director of a digital agency.
- CTO / Head of Engineering when a specific external delivery need is visible.
- Owner of a service business with a verified booking, lead-capture, or internal-systems problem.

Use LinkedIn's People and Posts search pages for manual review when public search indexing does not reveal enough. Do not turn a query pack into an automated scraper. Search URLs should open LinkedIn search results for the user to inspect.

## Research protocol

For each candidate:

1. Open the source result or use a reliable public source snippet. Do not claim to have inspected content that was not accessible.
2. Verify the person's current company and title from a LinkedIn profile or an official company team page.
3. Verify the business need from a LinkedIn post, public company page, job description, product launch, or other primary source.
4. Record the source URL, source type, source publication date, and date checked.
5. Write an evidence summary that distinguishes the observation from the interpretation.
6. Explain why the need maps to one specific service.
7. Check the prior prospect registry before adding the person to the daily queue.

If a company website has a usability issue, describe the exact page and observed issue. Do not use subjective phrases such as "the website is terrible" or infer that the owner wants a redesign. A visible issue is a possible opportunity, not proof of buying intent, unless the company or decision-maker has also signaled a relevant project or need.

## Message quality standard

The user dislikes generic, salesy, overly polished AI copy. The message must sound like a real person who has a specific reason to contact this particular business owner.

### Do

- Start from the actual post, project, launch, website issue, or business detail that justified qualification.
- Make the relevance clear without listing every service.
- Use the one portfolio example that best supports the need, only when it adds proof.
- Keep the connection note short enough for the character limit displayed in LinkedIn's current UI.
- Write the first DM as a natural continuation after acceptance.
- Use one thoughtful question at most, and only when it gives the recipient something meaningful to answer.
- Match the prospect's professional tone and language.
- Use the user's calibrated voice profile when one exists.

### Do not

- Open with "I came across your profile" or "I thought it would be nice to connect."
- Use generic flattery (impressive journey, inspiring work, love what you're building).
- Claim familiarity or a relationship that does not exist.
- Invent a problem, launch date, hiring plan, budget, metric, or technical requirement.
- Use a generic CTA such as "open to a quick chat?" when there is no reason for a meeting.
- Send a long service menu or dump the user's portfolio.
- Use fake urgency or claim the user has a ready-made solution without evidence.
- Write a first message that could be sent unchanged to dozens of unrelated prospects.

Avoid em dashes and corporate filler by default. Do not over-correct the user's voice into a stiff, formal SDR style. If the message feels like a template, rewrite it from the actual evidence or withhold it.

## Contact-path rules

| Relationship / feature | Draft to prepare |
|---|---|
| Not connected | Connection request note only; prepare the post-acceptance DM separately |
| First-degree connection | Direct LinkedIn DM |
| Open Profile visibly available | Direct message only if the UI actually offers it |
| InMail available and user chooses it | InMail draft; note that credits may be limited |
| No permitted route visible | Mark unavailable; do not pretend a normal DM can be sent |

Do not state that the user can send unlimited DMs. Do not automate the send.

## Follow-up rules

- One follow-up after 5–7 business days is the default only when the invitation or DM was actually sent and there has been no response.
- The follow-up must add a new useful observation, example, or answer. "Just checking in" is not enough.
- If the prospect says "not now", use the timing they gave.
- If the prospect declines or asks not to be contacted, stop and mark not interested.
- If the prospect asks a question, answer that question before steering toward a call.
- If the prospect expresses interest, clarify their actual need before proposing a package or price.

## Quality gate before presenting a draft

Ask:
1. Is the reason to contact this person specific and source-backed?
2. Does the message refer to the actual reason, rather than merely the person's title?
3. Is the user offering something relevant and true?
4. Is the contact path accurate?
5. Would this message still make sense if the prospect's name and company were changed? If yes, it is too generic.
6. Does it avoid a premature meeting ask?
7. Does it sound like the user's calibrated voice?

If any answer fails, rewrite or withhold the draft.

## Research failure and recovery

- If the LinkedIn page is restricted, use the public post or official company evidence and mark the profile fields that remain unverified.
- If search results are stale, narrow the query to recent posts or use LinkedIn's native search filters.
- If the company is real but no buyer need is found, do not manufacture intent. Keep it out of the qualified ten.
- If two sources conflict, record both and mark Needs Review.
- If a profile URL cannot be verified, do not add it to the qualified list.

The goal is ten strong conversations worth starting, not ten messages at any cost.
